# Product Philosophy

## Core belief

MoneyGap AI optimizes **businesses**, not websites.

## Finding standard

Every MoneyGap finding must answer:

1. **What is missing?** — Exact absence (never only what exists)
2. **Why does it matter?** — Plain English outcomes (trust, leads, sales, retention, authority, revenue)
3. **Business impact** — Concrete effects on growth
4. **Estimated opportunity** — AI Estimate with clear non-guarantee framing
5. **Why might it be missing?** — Likely causes (never absolute assumptions)
6. **How should it be fixed?** — Quick Wins · Medium Effort · Long-Term Strategy
7. **Priority** — Critical / High / Medium / Low
8. **Difficulty** — Easy / Medium / Hard (or equivalent)
9. **Estimated implementation time**
10. **Expected ROI** — Directional score/stars with rationale

Plus:

- **Confidence Score** + **Confidence Level** (Very High / High / Medium / Low)
- **Evidence Summary** + supporting signals
- **Business reasoning** (“Why did MoneyGap recommend this?”)
- **Source of detection** (module / Trust Engine)
- **Opportunity Index™**
- **Helpful resources** when appropriate
- **Status** — Found / Not Found / Partial (detection)

See `docs/trust-engine.md` (Phase 11).

## Language rules

- Prefer business language over jargon.
- Never present estimates as certainty.
- Never stop at technical analysis.
- Always explain the path to revenue.

## Engineering rule

Before implementing any feature, ask:

1. Does this help a founder see missing growth opportunity?
2. Does the output answer the north-star question?
3. Does the UI make the next action obvious?
4. Would a founder open this every morning to know **exactly what to work on next**?

If not, redesign the feature — do not ship noise.
